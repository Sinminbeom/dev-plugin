# 세션 규칙

각 룰의 enforce 방식은 다음과 같이 표시한다.

- `[hook]`: 자동 차단 (실행 시점에 hook이 차단)
- `[자동 검증]`: PR 생성 시점 등에서 절차적으로 검증
- `[사람 판단]`: 운영 원칙. Claude가 자기보고하고 사람이 결정

## 기본 원칙

- **1 세션 = 1 Task Issue = 1 PR** (의도 anchor). `[자동 검증]`
- 모든 commit / PR은 Issue 번호를 참조한다. `[hook]`
- PR description에 close하는 Issue를 명시한다. `[자동 검증]`
- 세션 종료 시점은 **PR 생성 완료**다. PR 리뷰 코멘트 반영은 같은 세션의 연장으로 처리한다. `[사람 판단]`
- 세션 중 발견한 추가 작업은 즉시 보고한다. 새 Issue는 사용자 확인 또는 `/session-start`로 만들고, 분리 기록은 PR 생성 전 마감한다. `[사람 판단]`
- 관련 없는 작업 전환 시 `/clear`로 context를 초기화한다. `[사람 판단]`

## 브랜치 작업공간

운영 기준 브랜치(정의는 `github.md` "브랜치 작업공간" 참고) 직접 commit/push 차단은 hook으로 enforce된다. `[hook]`

- 세션마다 전용 branch(또는 worktree)를 사용한다. `[사람 판단]`
- 한 branch는 하나의 Task Issue만 갖는다. `[사람 판단]`

## 커밋 메타데이터

Claude attribution 차단은 hook으로 enforce된다. `[hook]`

## Task 분리 기준 (구현 전 설계 단계)

구현을 시작하기 전에 Task Issue를 분리해야 하는지 먼저 판단한다. 다음 중 하나라도 해당하면 분리 신호다. `[사람 판단]`

- 목표가 둘 이상인 경우
- 완료 기준이나 검증 방법이 다른 경우
- 선행 설계 결정이 후속 구현 방향을 바꾸는 경우
- 현재 Task 목적과 직접 관련 없는 리팩터링·정리·정책 변경이 섞이는 경우
- API, 데이터 모델, 권한, 배포, 보안, 아키텍처 경계를 바꾸는 경우

## 현재 세션 포함 가능 예외

다음 변경은 단일 의도 안의 자연스러운 동반 변경으로 본다. 분리하지 않고 현재 세션에 포함한다. `[사람 판단]`

- 단일 설계 의도 아래의 반복적 변경
- 같은 규칙을 여러 문서나 스킬에 동기화하는 변경
- 테스트·문서·예시처럼 본 작업 검증을 위한 변경
- 포맷팅, 생성 파일, lockfile 등 실질 설계 판단이 없는 변경
- 오타, 명백한 주석 수정
- 현재 변경에 직접 연결된 아주 작은 보조 수정

## 세션 중단 기준

다음 상황은 즉시 사람에게 알리고 멈춘다. `[사람 판단]`

- 현재 Task Issue 범위를 벗어난 구조 변경, 리팩터링, 정책 판단이 필요한 경우
- 외부 시스템 상태(권한·배포·운영 데이터)나 사람의 정책 판단이 필요해서 진행 불가한 경우 (일반적인 의존 코드 조회는 정상 작업이므로 중단 사유가 아니다)

세션 중단 여부는 사람이 최종 판단한다.

### 설계 점검 신호

하드 중단이 아니라 *설계가 흐트러지지 않았는지 점검하라*는 신호다. 켜지면 Claude는 진행 상황을 보고하고 분리 신호 5가지로 단일 의도인지 자기보고한다. `[사람 판단]`

- 수정 파일 5개 초과 시점
- 변경 200줄 초과 시점

## 세션 중단 후 처리 절차

중단이 결정되면 진행분을 작업 브랜치에 WIP 커밋으로 보존하고, 중단 사유와 발견한 추가 작업을 Issue 코멘트로 기록한 뒤, 중단 유형에 따라 마무리한다. 상태 표시는 open/close와 close 사유로만 하고 라벨은 쓰지 않는다. `[사람 판단]`

- **재개 예정** (외부 블로킹 등): Issue를 open으로 유지한다.
- **후속 Issue로 대체** (범위 재편·분리): 후속 Task Issue를 만들고, 원 Issue는 후속 Issue를 링크한 뒤 `not planned` 사유로 close한다.

## 범위 이탈 감지 책임

범위 이탈 감지는 **Claude의 자기보고 책임**이다. 사람은 감지된 이탈에 대한 *대응 결정*만 한다. `[사람 판단]`

## 초기 저장소 예외

```text
Repository 생성 -> 초기 커밋 -> Issue 생성 -> branch(또는 worktree) -> 작업 -> PR
```

초기 환경 구성 이후부터는 일반 규칙을 따른다.
